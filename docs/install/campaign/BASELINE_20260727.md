## Discovery and installation findings

The repository documentation makes the intended pair discoverable:
`nq-witness` observes and `nq-monitor` stores, evaluates, and renders. The
actual public release path is unusable because there is no latest binary
asset at the documented URL. Curl reports a generic 404; the command does not
explain that no release is available or point to the source alternative.

The source alternative is buildable from an empty dependency cache and
without siblings. It is not a minimal operator installation:

- the `cargo` command visible on this host was a Rustup proxy;
- the pinned `rust-toolchain.toml` caused it to download a complete default
  toolchain, including components not needed merely to run NQ;
- the build required public Git, Rust distribution, and crates.io access;
- build prerequisites are prose assumptions rather than an executable
  preflight;
- release compilation emitted four developer-facing dead-code warnings;
- the copied binaries could not report their versions.

No inherited environment leak was observed. The harness passed exactly ten
documented, non-secret environment variables and used fresh Cargo, Rustup,
XDG, and HOME directories. The remaining known installation leaks are
repository/package defects documented in the archaeology: a private Caddy
deployment in `deploy/examples`, an author-local path in toolchain
commentary, and production instructions that require a source checkout to
obtain units and configs.

## Configuration and literal-documentation findings

The loopback-only, notification-free quickstart configuration is conservative.
However, the public quickstart says “Save this as” twice without giving a
literal command or shipping those specimens as release files. The completed
source run records `operator_assistance: true` for materialization. A literal
operator who refuses to infer an editor or redirection cannot proceed past
that point.

Public HEAD had no `config validate` command. The harness correctly did not
invent one. Commit `08e2449` adds strict, side-effect-free validation locally,
but a future clean-room run must verify the published artifact before that
repair counts as installation evidence.

## Failure and recovery findings

The occupied-port refusal did prevent the new witness process from remaining
alive and created no monitor database. The two relevant messages were split:
an informational line named `127.0.0.1:9847`, while the terminal error only
said “Address already in use.” It did not say:

- which process owns the port;
- how to inspect the conflict;
- whether any checks ran or state changed;
- whether choosing another port is safe;
- what the operator should do next.

The release 404 is similarly non-actionable at the product level. The version
probe failures make it impossible to confirm which release is installed.
These are recoverability defects, not operator mistakes.

No supported prior release artifact was available, so no upgrade specimen was
manufactured. No removal or product-reset procedure is documented. The
database and its sidecars are durable evidence; deleting them is not a safe
substitute for an archive-first reset.

## Packaging and constellation composability

At public HEAD, the only demonstrated distribution unit is the source
workspace. At the local working line, `nq-protocol`, `nq-witness`, and `nq`
now have bounded package manifests, but their crates and dependency order are
not yet published. `nq-monitor` still reaches workspace path packages, and
the operational `nq-witness` binary is currently produced by the package
named `nq-monitor-agent`. That compatibility arrangement can be valid during
migration, but it is not yet independently installable packaging.

The clean source build proves absence of sibling-checkout dependence for the
public workspace. It does not prove that `nq`, `nq-witness`,
`nq-monitor-agent`, and `nq-monitor` can be installed, upgraded, or released
independently.

## Recommended changes

1. Publish a real versioned release before advertising
   `releases/latest/download`; fail with an NQ-specific discovery message
   when no release exists.
2. Publish an archive or packages containing binaries, generic configs,
   service units, checksums, version metadata, and an install/removal
   manifest. Production installation should not require a source clone.
3. State source prerequisites explicitly, including Rustup behavior, network
   endpoints, native toolchain needs, disk space, and supported Linux targets.
4. Ship the quickstart configs as artifacts or provide literal commands that
   create them exactly.
5. Clean-room-test the `08e2449` validation and occupied-port repairs from a
   published or deliberately exported source revision.
6. Make bind failures name the address, state what did and did not run or
   mutate, and give one safe inspection command.
7. Make package, binary, help, and version names agree throughout release,
   Cargo, CI action, and operator docs.
8. Publish/version leaf packages in dependency order and test monitor-only,
   witness-artifact-only, and local-check-agent-only installs without sibling
   source paths.
9. Add archive-first removal and reset instructions that distinguish durable
   evidence, configuration, liveness exports, binaries, caches, service
   identity, and backups.
10. Run the first-success specimen on a disposable VM or container with no
    listeners on 9847/9848; do not stop unrelated observed services merely to
    obtain a green transcript.
